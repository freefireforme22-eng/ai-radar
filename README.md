# رادار هوش مصنوعی — AI Radar

بولتن خبری فارسی حوزه هوش مصنوعی برای تلگرام. هر ۶ ساعت یک پیام با قالب
**Rich Message** (Bot API 10.1+) منتشر می‌کند: توگل‌های تودرتو، چک‌لیست،
جدول، نقل‌قول بازشو و فرمول LaTeX.

کانال: [@ai_newsBY](https://t.me/ai_newsBY)

## چرا از نو نوشته شد

پروژه قبلی (فورک رصد نیوز) متن فارسی را با **جدولِ جانشینی کلمه** می‌ساخت، نه
با ترجمه. هر عبارتی که در آن جدول نبود انگلیسی می‌ماند و بعضی مدخل‌ها هم غلط
بودند — مثلاً `GPT` به «جی‌پی‌یو» نگاشت شده بود که یعنی GPU. مترجم واقعی در کد
بود ولی فقط به‌عنوان fallback اجرا می‌شد.

اینجا ترجمه **تنها مسیر** است و هر متن قبل از انتشار از یک دروازه کیفیت
(`llm.audit`) عبور می‌کند. متنی که رد شود با مدل قوی‌تر بازتولید می‌شود و اگر
باز هم رد شد، **منتشر نمی‌شود**.

## معماری

```
sources.py   RSS/Atom → فیلتر موضوعی AI → حذف تکراری‌ها → Story
enrich.py    triage با LLM → ترجمه فارسی → دروازه کیفیت → اصلاح نویسه‌گردانی
render.py    ساخت payload ریچ (توگل تودرتو، چک‌لیست، جدول، LaTeX)
telegram.py  ارسال + fallback متنی برای کاربران غیرپریمیوم
run.py       اجرای کل زنجیره
```

بدون هیچ وابستگی بیرونی — فقط کتابخانه استاندارد پایتون. `pytest` تنها برای تست.

## نقطه‌های کلیدی طراحی

**دروازه کیفیت ترجمه.** `llm.audit()` نسبت حروف فارسی و کلمات لاتین
ترجمه‌نشده را می‌سنجد. نام‌های خاص (`OpenAI`, `GPT-5.2`, `MMLU`) مجازند، بقیه
باقیمانده ترجمه‌نشده شمرده می‌شوند. علت رد شدن هم گزارش می‌شود، پس اشکال‌یابی
ممکن است.

**اصلاح نویسه‌گردانی.** مدل‌ها گاهی «Gemini 3.8 Flash» را در تیتر
«جمینای ۳.۸ فلش» می‌نویسند و در متن درست. `_repair_translit()` این را
قطعی برمی‌گرداند. مرزبندی واژه ضروری است: بدون آن «پرو»→`Pro` کلمه «پرونده» را
به «Proنده» تبدیل می‌کرد — این باگ واقعاً در یک پیش‌نمایش زنده رخ داد و تست
`test_translit_never_corrupts_ordinary_words` نگهبان آن است.

نکته‌ای که به‌سختی پیدا شد: املای فارسیِ یک برند ثابت نیست و مدل هر بار
جور دیگری می‌نویسد. یک بولتن زنده «جمینی» منتشر کرد چون در جدول فقط املای
«جمینای» بود؛ و چون واژه پیشین فارسی می‌ماند، قاعدهٔ پسوند («فلش») هم دیگر
فعال نمی‌شد. حالا همهٔ املاهای دیده‌شده در جدول هستند.

**عددِ نسخه با حروف.** یک اجرای زنده «نسخه صفر.سی‌وسهار» را برای `0.34` منتشر
کرد. هیچ نگهبانی جلویش را نگرفت: متن صددرصد فارسی است پس `audit` قبولش می‌کند و
`_fa_digits` فقط رقم را به رقم نگاشت می‌کند. الان `_fix_spelled_version()` عدد را
از تیتر انگلیسی منبع بازمی‌نویسد، و اگر منبع عددی نداشته باشد آن خبر
**منتشر نمی‌شود** (عدد از خودش نمی‌سازد).

**غلط املایی فارسی.** «آامازون» به‌جای «آمازون» در یک اجرای زمان‌بندی‌شده
منتشر شد. این هم از دید `audit` بی‌عیب است. `_fix_spelling()` روی همهٔ فیلدهای
قابل‌مشاهده اجرا می‌شود و قاعدهٔ عمومی «آ + الف» را هم پوشش می‌دهد.

**حذف خبر تکراری.** یک رویداد از چند منبع می‌آید با URLهای مختلف. تشابه Jaccard
روی کلیدواژه‌های تیتر + معیار containment این‌ها را یکی می‌کند؛ منبع اصلی
(بلاگ خود شرکت) برنده است و بقیه به‌عنوان «پوشش خبری دیگر» ذکر می‌شوند.

**فیلتر موضوعی.** فیدهای عمومی مثل Hacker News مطالب غیرمرتبط هم دارند
(«Paint.net 5.2 alpha now runs on Linux»). فیلتر قبل از triage اجرا می‌شود تا
توکن هدر نرود و خبر بی‌ربط وارد بولتن نشود.

**تاریخ جلالی.** تبدیل بدون وابستگی، با `jdatetime` روی ۱۲۰۰ روز پیاپی
مقایسه شده: صفر اختلاف.

## نام‌های اسکیمای ریچ (تست‌شده روی سرور تلگرام)

چند نامی که در مستندات منطقی به نظر می‌رسند رد می‌شوند:

| درست | رد می‌شود |
|---|---|
| `heading` (+ `size` عددی ۱–۶، الزامی) | `section_heading`, `title`, `h1` |
| `pre` | `preformatted`, `code` |
| `blockquote` | `block_quotation`, `quotation` |
| `expandable_blockquote` | `expandableBlockQuotation` |
| `mathematical_expression` | `math`, `latex`, `equation` |
| `voice_note` | `voiceNote` |

`details` به `summary` نیاز دارد (نه `title`)، و آیتم‌های `list` محتوای خود را
داخل `blocks` می‌گذارند. `details` تودرتوی `details` مجاز است — ساختار اصلی این
کانال همین است.

## اجرا

```bash
export TG_BOT_TOKEN=...        # بات باید ادمین کانال با حق ارسال باشد
export TG_CHANNEL_ID=@ai_newsBY
export OPENAI_API_KEY=...
export OPENAI_BASE_URL=https://.../v1

python -m radar.run --dry-run              # ساخت بولتن بدون ارسال
python -m radar.run --preview <chat_id>    # ارسال آزمایشی به یک چت خصوصی
python -m radar.run                        # انتشار در کانال
python -m radar.run --plain                # نسخه متنی (بدون ریچ)
python -m pytest tests/ -q                 # ۳۴ تست آفلاین
```

## زمان‌بندی

`.github/workflows/radar.yml` هر ۶ ساعت اجرا می‌شود. `concurrency` جلوی اجرای
هم‌زمان را می‌گیرد چون دو اجرای موازی `data/seen.json` را خراب می‌کنند و خبر
تکراری منتشر می‌شود.

Secrets لازم: `TG_BOT_TOKEN`, `TG_CHANNEL_ID`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`.

### چرا فقط به GitHub Actions تکیه نمی‌کنیم

کانال قبلی بی‌صدا مرد و دلیلش در ریپوی خودش ثبت است: ۷۹۰ اجرای زمان‌بندی‌شده،
۵۰۰ اجرا **ناموفق** با همین یک خطا:

```
AttributeError: 'SubaruRadar' object has no attribute '_escape_markdown'
```

هر ۱۵ دقیقه اجرا می‌شد، هر بار می‌افتاد، و کسی خبردار نشد.

خطر دومی هم هست: GitHub زمان‌بندی یک ریپوی تازه را با تأخیر ثبت می‌کند و زیر بار
هم اجراها را بی‌اطلاع می‌اندازد. پس یک تور ایمنی سمت سرور وجود دارد:

```bash
python3 /data/.hermes/scripts/radar_safety_net.py --check   # فقط گزارش
python3 /data/.hermes/scripts/radar_safety_net.py           # اگر کهنه بود، منتشر کن
```

اگر آخرین انتشار واقعی بیش از ۸ ساعت قبل بوده باشد، از خود سرور منتشر می‌کند.
معیارش commit روی `data/seen.json` است نه «اجرای موفق»، چون یک اجرای
`--dry-run` هم موفق تمام می‌شود و می‌تواند یک کانال مرده را ۸ ساعت دیگر پنهان
کند. اوج مصرف حافظهٔ اجرای سمت سرور اندازه‌گیری شده: **۴۴ مگابایت**.
در مسیر سلامت هیچ چیزی چاپ نمی‌کند تا کران‌جاب پیام بی‌مورد نفرستد.

## محدودیت

قالب ریچ فقط برای کاربران **پریمیوم** تلگرام کامل رندر می‌شود. `--plain` و
مسیر fallback خودکار برای بقیه است.
